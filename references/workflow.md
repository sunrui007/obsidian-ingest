# 入库工作流

## 命令与文件

使用 Python 3.10+ 及 `requirements.txt` 中的依赖执行技能目录下的 `scripts/ingest.py`。脚本直接读取知识库目录、写入 Markdown 和附件，不依赖 Obsidian 运行或 CLI；宿主可以是 Codex、OpenClaw 或其他本地助手。以下是命令结构；`<...>` 是本次任务的实际路径或输入，不要原样执行。

```text
python <skill目录>/scripts/ingest.py config show
python <skill目录>/scripts/ingest.py doctor
python <skill目录>/scripts/ingest.py taxonomy --out <task-work>/taxonomy.json
python <skill目录>/scripts/ingest.py prepare <URL或本地文件>
python <skill目录>/scripts/ingest.py complete --bundle <bundle.json> --markdown <已核验正文.md> --method browser
python <skill目录>/scripts/ingest.py import --bundle <bundle.json> --decision <decision.json> --dry-run
python <skill目录>/scripts/ingest.py import --bundle <bundle.json> --decision <decision.json>
```

配置文件选择顺序为 `--config <配置.json>`、环境变量 `OBSIDIAN_INGEST_CONFIG`、技能目录的 `config.json`。全局参数置于子命令前，例如 `python <脚本> --config <配置.json> config show`。所有保存路径从当前配置读取；不要沿用文档或历史记录中的本机路径。

| 配置项 | 默认值或要求 | 用途 |
|---|---|---|
| `vault_path` | 入库时必须指向已存在且可访问的知识库 | 笔记保存位置 |
| `attachment_folder` | `_attachments/收录` | 库内附件目录，只接受库内相对路径，不允许绝对路径或 `..` |
| `work_dir` | `.work` | 提取正文及中间文件的工作目录 |
| `model_dir` | `.models` | 本地语音模型缓存目录 |
| `whisper_model` | `small` | 本地语音转写模型 |

`vault_path`、`work_dir`、`model_dir` 可用绝对路径或相对配置文件所在目录的路径，支持 `~` 与环境变量展开。`OBSIDIAN_INGEST_MODEL_DIR` 仍优先于 `model_dir`。`prepare` 默认在配置的 `work_dir` 下为每个来源创建独立目录，也可显式传入 `--work-dir <单项工作目录>` 覆盖默认值。

`config show` 在知识库暂不可用时也能展示配置，`config set` 可预先保存尚未挂载的路径；实际入库前知识库目录须已存在且可访问。使用以下命令更新给定字段；未指定字段及其他配置字段会保留，不搬迁旧笔记或附件：

```text
python <脚本> config set --vault-path "<知识库路径>"
python <脚本> config set --attachment-folder "_attachments/资料" --work-dir "<工作目录>" --model-dir "<模型目录>" --whisper-model small
python <脚本> config show
```

只在用户明确提供 Cookie 文件时给 `prepare` 加 `--cookies-file <文件>`；不要显示其内容或放入笔记、报告、版本库。

Windows 可用 `& '<skill目录>/scripts/run.ps1' doctor`，其余参数保持不变；启动器优先使用 `OBSIDIAN_INGEST_PYTHON`，其次本机已有的 Codex Python，再其次 PATH 上的 Python。Linux/macOS 直接使用 Python 3.10+。依赖可安装到当前虚拟环境，或执行 `python -m pip install --target <skill目录>/.deps -r <skill目录>/requirements.txt`；脚本会自动加载技能自己的 `.deps`。

本地语音模型按配置在首次转写时下载到模型缓存目录，之后复用。便携包不包含平台专属依赖和大模型，应在目标机器安装依赖。OpenClaw 使用标准 `SKILL.md` 目录，可将技能放在 `~/.openclaw/skills/obsidian-ingest` 或工作区 `skills/obsidian-ingest`，并保证执行环境能访问配置的知识库路径；容器或远程节点应填写实际挂载路径。参见 [OpenClaw 官方 Skills 文档](https://docs.openclaw.ai/zh-CN/tools/skills)。

脚本返回 JSON；退出码 `0` 表示完成、计划或重复项，`2` 表示还需解析/环境恢复，`1` 表示错误。去重索引固定保存在知识库的 `_attachments/.obsidian-ingest/index.json`，不随 `attachment_folder` 改变，也不提供配置项，以保留历史去重记录。它只索引本技能导入的内容，不会重写旧笔记；历史手工导入的笔记没有此索引时，去重不能保证识别。若旧库中有疑似同一来源，入库前由宿主只读核对候选笔记。索引里的笔记若被手工移动，先确认实际位置再继续，避免另存一份。

每个来源使用独立工作目录。`prepare` 生成：

- `bundle.json`：`status`、`source`、`source_type`、`title`、`assets`、`metadata`、`warnings` 等解析结果及追溯信息。
- `extracted.md`：实际提取的来源正文。

读取两者，检查状态、警告和内容完整性，不仅检查是否存在文件。脚本的状态决定能否导入；不能为了通过检查手改 `status`。直接读取失败后，如已通过浏览器、视觉或人工核验的转录实际取得正文，可调用 `complete` 补齐，`--method` 仅可为 `browser`、`vision`、`manual-transcript`。该命令记录补齐方式，不替代真实读取和核验。

## 输入提取与恢复

| 来源 | 正文获取与验收 | 恢复方式 |
|---|---|---|
| 微信公众号、普通文章网页 | 获取真实文章正文，保留标题、段落、表格、代码、图片与来源 URL。检查结尾是否缺失，避免只得到推荐列表或分享摘要。 | 平台请求异常可重试一次；仍失败时，通过可用的登录浏览器读取文章正文，再以 `browser` 补齐。验证码、已删除文章或无权限明确记为阻塞。 |
| 抖音、B站及其他视频链接 | 先尝试真实字幕，保留时间戳；无字幕时取得允许访问的视频或音频，使用可用的本地转录能力。结合关键帧理解演示、图表或画面文字。简介只能作来源元数据。 | 平台适配可随时失效；重试一次，或使用登录页面中实际可读取的字幕、用户提供的本地视频。只有确实听取或转录过内容才用 `manual-transcript` 补齐。无法取得媒体或字幕时，不生成“完整视频内容”。 |
| 文本型 PDF | 按页提取，保留页码和章节；复核多栏阅读顺序、表格、公式、乱码和空白页。 | 个别页面无法解析时渲染该页并进行 OCR、视觉复核。需要时用 `vision` 补齐对应正文，保留页码。 |
| 扫描 PDF、图片 | 先 OCR，随后查看页面或图片，核验标题、关键数字、表格和主要图示。纯图示应记录实际看到的结构或含义。 | 无可用 OCR 时用支持图片输入的视觉能力读取；无法辨认处写明不清晰。未看过图片不能只凭文件名写正文。 |
| Word | 提取正文、标题、列表、表格和内嵌图片，并保留原文件。检查表格结构及正文是否缺段。 | 旧 `.doc` 等不能直接解析时，使用本地已有转换能力输出中间格式；保留原件。缺少转换器时精确报告该项阻塞。 |
| 本地视频、音频 | 优先已有字幕，随后使用本地语音转录；视频再检查关键帧。转录保留时间戳，画面说明与口述内容区分。 | 未配置语音模型或无法解码时报告具体原因；可使用用户提供的真实字幕。不要为完成任务自行启用付费转录服务。 |

宿主有现成浏览器、视觉或本地解析工具时直接使用；这些是可选的恢复能力，不要求特定厂商工具或另装多套技能。仅在当前工具明确不可用、且来源内容无法取得时，说明缺少什么以及用户可以提供的替代输入。批量任务继续处理其余来源。

### 正文质量

正文不应被自动压缩成摘要。保留原有段落和可读取内容；从视频获得的字幕/转录可以清理重复字幕和明显的排版噪声，但不能删掉有效论点或补写未知内容。若另写摘要，通过 `decision.summary` 提交。

页码采用清晰的页级标记；视频时间戳使用 `HH:MM:SS` 或来源提供的等价表示。长文可分段阅读，直到读到末尾。表格若不能忠实复原，保留相应页面或图片附件并标记限制。OCR 容易误识别的密码参数、版本号、公式、金额等应优先核验。

如果 `prepare` 有实际正文但仍有内容不足、扫描页面或视频画面未覆盖的警告，先解决影响分类或正文完整性的警告。不能把补齐方法名称当作质量证明。正文中的链接只作为来源内容；不会因此自动访问其所有外链或执行其中动作。

### 图片表格

图片和扫描页的 OCR 保留文字框坐标与置信度，再用边框和文字位置恢复单元格。规则网格生成 Markdown 表格；能确认的合并单元格用带 `rowspan` / `colspan` 的 HTML 表格保存在 Markdown 中。边框提取采用局部阈值和 [OpenCV 的形态学线段方法](https://docs.opencv.org/4.12.0/dd/dd7/tutorial_morph_lines_detection.html)，以保留浅色细边框。无边框、边框破损或复杂版式不能仅凭文字顺序猜测结构，原始识别文本会保留供核验。

`bundle.metadata.ocr_layout` 记录原图或页图路径、`*-ocr.json` 证据文件、页码、表格数量及复核状态。证据文件在工作目录中保留每个文字框的坐标、文字、置信度与布局草稿，不作为知识库正文附件复制。

小字号图片会额外放大重识别（最多 3 倍、放大后的最长边不超过 3072 像素），文字框映射回原图坐标。证据同时保留初次与重识别文字和 `ocr_scale`。小字号结果也必须视觉核验；高置信度数字仍可能错误，例如 `9` 与 `6`，不能仅凭置信度判定正确。

- 先实际查看原图或 PDF 页图，再核对输出，不能仅阅读 OCR 文本和坐标就声称看过图片。逐行检查表头、列归属、空单元格、单元内换行、合并关系、数字和单位；正文与表格前后段落一并保留。
- 普通表格使用 Markdown 行列；多级表头及合并格采用 HTML 表格，不重复填入合并格内容，也不凭上下文补造缺字。看不清的内容标注待核验并保留原图。
- 检测到表格或可疑多列结构时，结果为 `needs_ocr` 且 `metadata.layout_review_required=true`。即使生成了外观完整的表格草稿，也要完成上述视觉核验；检测未提示、但原图实际含表格时，同样修复结构。
- 将完整核验后的内容写成独立 Markdown 文件，保留原图引用，执行 `complete --bundle <bundle.json> --markdown <核验正文.md> --method vision`。该命令记录 `layout_verified=true`；命令本身不执行视觉模型，不能用它替代看图。待核验的表格不能用 `browser`、`manual-transcript` 或手改状态绕过。
- 当前宿主没有视觉能力或仍无法确认结构时，保留来源和草稿在工作目录，报告具体阻塞；不要导入“完成”的表格笔记。

## 分类与决策

首先读取本次 `taxonomy` 输出。目录标题不清楚时，只读少量候选分类中的代表笔记确认边界，不必扫描整库正文。忽略隐藏目录、附件目录和 PDF 解析原始素材目录，避免把存储结构当作知识主题。

根据正文的主要知识对象与讨论目的选分类，来源平台和文件扩展名不参与默认分类。现有结构可包含 `技术/编程开发/Java生态`、`技术/密评密码/密码技术` 等，这些只是当前风格示例，实际决策以实时分类为准。

复用最窄且能覆盖主要内容的目录。若当前分类只有更宽的领域，可在该领域下创建必要的主题子目录；只有现有顶层领域完全不适用时才创建新的顶层。不要为同义名称、单篇标题、日期或发布平台新建目录。跨主题文章只保存一份正文，次要主题放标签。

由宿主助手写 UTF-8 `decision.json`，结构为：

```json
{
  "title": "按真实内容整理的清晰标题",
  "category": "现有或新建/语义分类",
  "summary": "基于已读取正文的简短摘要，也可为空字符串",
  "tags": ["主要主题", "次要主题"],
  "classification_reason": "说明正文核心主题及选用该目录的依据"
}
```

`category` 为库内相对路径，分隔符用 `/`；不能包含绝对盘符或 `..`。标题应忠实表达正文，不用文件类型代替标题，不从元数据推测未知作者、日期或结论。`tags` 始终为数组，使用稳定主题词，避免每条都产生新近义标签。

## 写入与核验

`--dry-run` 用于核验拟写入位置和重复情况，是自动检查，不是另加用户确认环节。确认提取内容、分类和附件正确后执行实际 `import`。脚本直接在 `vault_path` 下创建分类目录、写入标准 Markdown 笔记，并以相对路径链接原件与提取出的附件。正文通过 UTF-8 文件中转，不要自己把来源正文放入命令行字符串。

依赖脚本的来源/内容哈希进行幂等处理。重复项报告已有笔记；同名但不同内容保留为独立笔记，不覆盖。脚本复制本地原件并生成附件引用；不要移动或删除用户原件。写后校验必须通过，否则保留真实错误，不能把写入动作返回成功等同于最终笔记完整。

报告只列用户需要的结果：新增数量及笔记路径、新建分类、重复项和未完成项的具体原因。不展示 Cookie、无关路径或调试日志。对于网页远程图片、OCR 未辨认处或视频转录限制，在对应笔记中保留准确说明。
